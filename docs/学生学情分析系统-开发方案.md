# 学生学情分析系统 · 开发方案

> 基于现有 **RuoYi-Vue 3.9.2 + PostgreSQL** 二次开发  
> 文档版本：v1.2 · 日期：2026-09-15  
> 目标：在保留系统管理能力的前提下，建设「采集 → 标注 → 导入 → 分析 → 预警 → 一生一册」闭环，并预留家长端开放接口。

| 决策项 | 结论 | 对方案的影响 |
| :--- | :--- | :--- |

## 1. 建设目标与范围

### 1.1 业务目标

| 目标 | 说明 |
| :--- | :--- |
| 作业/考试管理 | 新建作业、考试，维护题目结构 |
| 知识点标注 | 为每小题绑定 **一个或多个** 知识点及权重，并设置难度 |
| 成绩采集 | 支持按小题导入学生得分 |
| 薄弱点分析 | 按学生/班级/知识点多维统计（按权重分摊得分率） |
| 可视化 | 雷达图、柱状图、趋势图、热力图等 |
| 学情预警 | 规则引擎触发预警并通知 |
| 一生一册 | 学生个人学情档案；学生本人可登录查看 |
| 家长端预留 | 独立 OpenAPI + 鉴权模型，本期只出契约与 Stub |

### 1.2 本期不做（明确边界）

- 不做在线答题/阅卷引擎（只采「小题得分」）
- 不做自适应组卷算法（可二期）
- 不做家长端小程序/App 页面（仅预留接口）
- **不做 GameScreen 相关功能**（阶段 0 从工程中移除）

### 1.3 角色与权限

| 角色 | role_key | data_scope | 能力 |
| :--- | :--- | :--- | :--- |
| 系统管理员 | admin | 全部 | 全模块 + 用户/角色/部门 |
| 教务 | spas_jw | 自定义（演示挂学校 9100） | 学科、知识点、教师管理、成绩、分析、预警 |
| 任课教师 | spas_teacher | 本部门 | 作业/考试、导入成绩、分析、预警处理；可挂**多班级** |
| 班主任 | spas_bzr | 本部门 | 本班学生管理/导入 + 成绩 + 一生一册 + 预警处理 |
| 年级负责人 | spas_grade_leader | 本部门及以下 | 年级及下级班级学情、预警规则与处理 |
| 校级领导 | spas_school_leader | 本部门及以下 | **只读**总览、分析、预警、一生一册（写接口拒绝） |
| **学生** | **spas_student** | — | **登录后仅查看本人一生一册 / 本人分析（只读）** |
| 家长（预留） | — | — | 仅通过开放接口查看绑定子女学情 |

部门树沿用若依 `sys_dept`：学校 → 年级 → 班级。  
教师档案表 `spas_teacher`（类型 1–4 对应上表角色）；任课教师附加班级存 `spas_teacher_dept`。  
列表查询：默认 `@DataScope`；任课多班级时由 `SpasTeacherScopeService` 合并主属 + 附加部门过滤。  
路径访问：`SpasAccessService` 校验部门/学生；`assertCanWrite()` 拦截校级领导写操作。  
学生端强制校验「当前登录 user_id ↔ spas_student.user_id」。

## 3. 领域模型与数据库设计

### 3.1 核心概念

| 概念 | 含义 |
| :--- | :--- |
| Subject | 学科 |
| KnowledgePoint | 知识点（树形） |
| Student | 学生档案，**强制绑定**独立 `sys_user` |
| Paper | 试卷/作业 |
| PaperQuestion | 小题（满分、难度；**不存单个知识点**） |
| QuestionKnowledge | 题-知识点多对多（含权重） |
| ScoreDetail | 学生小题得分 |
| KnowledgeStat | 学情统计快照 |
| Warning / Portfolio | 预警与一生一册 |

### 3.2 ER 关系

```
Subject 1─N KnowledgePoint（parent_id 自关联）
Student 1─1 SysUser（user_id 非空、唯一）
Student N─1 Class(sys_dept)
Paper 1─N PaperQuestion
PaperQuestion N─M KnowledgePoint  via spas_question_knowledge(weight)
Paper 1─N ScoreBatch 1─N ScoreDetail
Student + KnowledgePoint → KnowledgeStat
```

### 3.3 表结构（PostgreSQL）

#### 3.3.1 `spas_subject` / `spas_knowledge`

学科表；知识点树（`parent_id`、`ancestors`、`difficulty_default`）。

#### 3.3.2 `spas_student` 学生（独立账号）

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| student_id | int8 PK | |
| student_no | varchar(32) 唯一 | 学号；默认作登录名 |
| student_name | varchar(64) | |
| gender | char(1) | |
| dept_id | int8 | 班级 |
| grade_year | varchar(16) | |
| **user_id** | **int8 NOT NULL UNIQUE** | **必须绑定 sys_user** |
| parent_mobile | varchar(20) | 家长端预留 |
| status / del_flag | | |

**开户规则（强制）**：

1. 新建/导入学生时，同一事务创建 `sys_user`  
2. `user_name` 默认 = `student_no`  
3. 初始密码可配（统一初始密码或学号后六位）  
4. 分配角色 `spas_student`；`dept_id` 与班级一致；`nick_name` = 姓名  
5. 停用学生 → 同步停用用户  

接口：`POST /spas/student`、`POST /spas/student/import`、`PUT /spas/student/resetPwd/{id}`。

#### 3.3.3 `spas_paper` / `spas_paper_question`

试卷字段同通用设计。  
小题表：`question_id, paper_id, question_no, question_order, full_score, difficulty, question_type, remark`。  
**不设 `knowledge_id`。** 唯一：`(paper_id, question_no)`。

#### 3.3.4 `spas_question_knowledge`（一期必建）

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| id | int8 PK | |
| question_id | int8 | |
| knowledge_id | int8 | |
| weight | numeric(6,4) | 同题合计必须 = 1.0000 |
| is_primary | char(1) | 主知识点（展示用，可选） |

约束：唯一 `(question_id, knowledge_id)`；每题至少 1 个知识点；`sum(weight)=1`（误差 ≤ 0.0001）。  
默认：选 N 个时前端均分 `1/N`，可手调。

#### 3.3.5 成绩 / 快照 / 预警 / 家长预留

- `spas_score_batch`、`spas_score_detail`（唯一键冲突则 UPDATE）  
- `spas_student_knowledge_stat`（按权重分摊后的快照）  
- `spas_warning_rule` / `spas_warning_record`  
- `spas_parent` / `spas_parent_student` / `spas_open_client` / `spas_coach_log`

### 3.4 字典

`spas_paper_type`、`spas_difficulty`、`spas_paper_status`、`spas_weak_level`、`spas_warning_level`、`spas_warning_status`。

## 4. 薄弱知识点分析算法（含多知识点分摊）

### 4.1 单题得分率

`rate_q = score / full_score`

### 4.2 多知识点分摊（核心）

题目 Q 绑定 K1..Kn，权重 w1..wn（Σw=1）。  
知识点 Ki 的样本权重：`sample_w = w_i × difficulty_w(Q)`（易/中/难默认 1.0/1.2/1.5）。

```
weighted_rate(K) = Σ(rate_q × sample_w) / Σ(sample_w)
attempt_count(K) = 关联到 K 的作答题目数（默认）
```

**示例**：第 3 题满分 10、得 6（rate=0.6），绑定「方程 0.6 + 应用题 0.4」，难度=中(1.2)：

- 方程 sample_w=0.72，应用题 sample_w=0.48，二者均计入 rate 0.6

### 4.3 薄弱等级（可配置）

| 等级 | 条件 |
| :--- | :--- |
| 关注 | weighted_rate &lt; 0.75 且 attempt_count ≥ 3 |
| 薄弱 | weighted_rate &lt; 0.60 且 attempt_count ≥ 3 |
| 严重 | weighted_rate &lt; 0.45 且 attempt_count ≥ 2 |

### 4.4 触发

导入成功异步重算；归档 / 每日 Quartz / 手动重算。  
实现：`KnowledgeStatCalculator`（`score_detail` ? `question_knowledge` ? `paper_question`）。

## 5. 功能模块：逐环节实现方法

### 5.1～5.2 学科 / 知识点

标准 CRUD + 树；删除前检查引用（知识点查 `spas_question_knowledge`）。

### 5.3 学生档案 + 独立开户

| 环节 | 实现方法 |
| :--- | :--- |
| 新建 | 事务：档案 + sys_user + 角色 + 回写 user_id |
| 导入 | 批量开户；失败行进报告 |
| 重置密码 / 停用 | 同步用户表 |
| 学生菜单 | 仅「我的学情」；`/spas/portfolio/mine` 禁止冒用他人 ID |

### 5.4 作业/考试（多知识点）

```
草稿 → 维护小题(题号/满分/难度/多知识点+权重) → 发布 → 导入 → 分析 → 归档
```

| 环节 | 实现方法 |
| :--- | :--- |
| 编辑器 | 知识点多选树；权重可编辑；「均分权重」 |
| 校验 | 至少 1 个知识点；权重和=1 |
| 保存 | 先存题目，再按题删插 `spas_question_knowledge` |
| 锁定 | 有成绩后默认禁止改知识点（配置项） |
| 默认难度 | 建议取所选知识点中最高默认难度 |

DTO 示例：

```json
{
  "questionNo": "3",
  "fullScore": 10,
  "difficulty": "2",
  "knowledgeList": [
    { "knowledgeId": 101, "weight": 0.6, "isPrimary": "1" },
    { "knowledgeId": 205, "weight": 0.4, "isPrimary": "0" }
  ]
}
```

### 5.5 成绩导入

按题号导入得分（与知识点无关）；成功后按关联表分摊统计。

### 5.6～5.8 分析 / 预警 / 一生一册

三块看板 + ECharts；预警引擎 + Quartz；一生一册教师看本班、学生看本人。  
知识点下钻展示「题目 → 多知识点及权重」。

### 5.9 家长端预留

`/open/v1/**`，鉴权隔离；本期 Stub + Postman。

## 8. 关键工程实现指引

### 8.1 模块

admin 只依赖 spas 等必要模块，**不依赖 gamescreen**。

### 8.2 配置

```yaml
spas:
  student:
    username-use-student-no: true
    init-password: "123456"
    force-reset-pwd: false
  paper:
    allow-change-knowledge-after-score: false
  analysis:
    difficulty-weight:
      easy: 1.0
      medium: 1.2
      hard: 1.5
    weak-thresholds:
      watch: 0.75
      weak: 0.60
      severe: 0.45
      min-attempts: 3
  open:
    enabled: false
    token-ttl-minutes: 120
```

### 8.3 多知识点统计 SQL 思路

```sql
select d.student_id, qk.knowledge_id,
       sum(d.rate * qk.weight * dw.w) / nullif(sum(qk.weight * dw.w), 0) as weighted_rate,
       count(distinct d.question_id) as attempt_count
  from spas_score_detail d
  join spas_paper_question q on q.question_id = d.question_id
  join spas_question_knowledge qk on qk.question_id = d.question_id
 group by d.student_id, qk.knowledge_id;
```

### 8.4 成绩 upsert

```sql
insert into spas_score_detail (...)
values (...)
on conflict (paper_id, question_id, student_id) do update set
  score = excluded.score,
  full_score = excluded.full_score,
  rate = excluded.rate,
  batch_id = excluded.batch_id;
```
