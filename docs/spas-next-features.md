# 知脉 · SPAS 新增功能方案（实考对齐 / 校次预警 / 标注门禁）

> 文档编码：UTF-8  
> 版本：v1.0 · 2026-09-20  
> 依托：现有「小题成绩 → 知识点掌握度 → 预警 → 干预」与「实考校次导入」两条数据链  
> 已交付：N1–N4，以及错因汇总、科目别名、补弱包导出。N6/N7 仍不做。

---

## 1. 背景

系统已能做知识点加权分析，也能导入各科实考分和校次。两条数据没有可靠对齐：实考按班内姓名匹配，重名会失败或错人；校次进退只在学生分析里展示，进不了预警和干预；试卷保存时会校验权重，但发布和成绩导入不再复核库里的标注，漏绑题目仍可能进入掌握度计算。

本期只补这三处，不改统计公式，不新增在线作答或 IRT。

## 2. 本期范围

| 编号 | 功能 | 验收标准 |
| :--- | :--- | :--- |
| N1 | 实考按学号优先匹配，并在学生分析中对照总分校次 | 有学号时不看姓名；无学号且同班重名则整行失败并提示填学号；学生分析可见单科相对总分的领先/落后 |
| N2 | 总分校次连续下滑、单科相对总分偏科，两条预警 | 规则可配置；导入实考成功后自动评估；预警可按现有流程转干预 |
| N3 | 发布试卷、导入小题成绩前复核标注 | 任一题未绑知识点，或权重之和不等于 1，则拒绝并列出题号 |

非目标：家长 App、在线阅卷、自适应组卷、把校次或掌握度当作升学奖惩依据。

## 3. N1 实考与小题成绩对齐

### 3.1 匹配规则

Excel 表头增加可选列「学号」（兼容 `studentNo`）。「姓名」仍保留。

| 行内数据 | 行为 |
| :--- | :--- |
| 填写了学号 | 只在所选班级内按学号精确匹配。找不到则该行失败，不回退到姓名 |
| 学号为空 | 按姓名匹配。0 人失败；2 人及以上失败，提示填写学号 |
| 学号、姓名都空 | 视为空行，跳过 |

模板下载预填该班学号和姓名。导出明细同样带学号列。已有只含「姓名」的表格仍可导入。

实考与试卷的关联沿用现有导入项：选择作业/考试后写入 `spas_exam.paper_id`。校次不回写小题得分，掌握度仍只来自小题成绩。

### 3.2 学生分析对照

「实考校次进退」表增加「相对总分」：最近一场该科校次减去最近总分校次。

- 正数：该科名次比总分更靠后（偏后）
- 负数：该科更靠前（领先）
- 展示阈值 ±20 名仅用于标签，不替代预警阈值

## 4. N2 偏科与校次预警

新增两种规则指标，运算符建议 `>`。导入实考且成功行数大于 0 后，只重跑这两类已启用规则，不重算知识点快照。

### 4.1 RANK_DROP 总分校次连续下滑

- 数据：`spas_exam_score.score_type = 2` 且 `school_rank` 非空，考试状态为已完成
- 场次：规则「考试场次 / 连续场次」`window_days`，至少 2，默认 3。只看该生最近 N 场总分
- 条件：这 N 场校次数字严格变大（名次变差）
- 指标值：末场校次 - 首场校次（变差的名次）
- 示例：`> 10` 表示最近 3 场连续退步，且一共退了超过 10 名

### 4.2 SUBJECT_IMBALANCE 单科落后总分

- 数据：该生最近一场同时有总分校次和至少一科校次的考试
- 指标值：`max(单科校次 - 总分校次)`，只统计正差距中的最大者；该科名次不差于总分时不触发
- 范围类型为学科时，只比较该学科名称与实考表头科目名一致的列
- 示例：`> 20` 表示至少有一科比总分名次落后超过 20 名
- `window_days` 不参与计算

预警正文写入科目或场次说明。转干预仍走现有预警记录，知识点绑定取该生当前最弱知识点（可能为空）。

可选种子（默认启用，可在预警规则里关闭）：`sql/spas_rank_warning_seed.sql`。无新表，不必改增量主脚本。

## 5. N3 标注质量门禁

保存题目时已有校验。本期在两个入口再查数据库中的标注：

1. 发布试卷 `PUT /spas/paper/publish/{paperId}`
2. 小题成绩导入 `POST /spas/score/import/{paperId}`

任一题目没有知识点，或该题权重合计与 1 的差超过 `0.0001`，抛出业务错误，列出最多 8 条题号说明。不自动改权重，不把未标注题当成 0 分知识点。

## 7. N4 轻量错因标签（已纳入交付）

不做在线答题。教师在学生分析「知识点 → 题目明细」中，对每道题勾选一个主错因：

| error_code | 含义 |
| :--- | :--- |
| reading | 审题 |
| calc | 计算 |
| concept | 概念 |
| skip | 未做 |

- 表：spas_error_tag，唯一键 (student_id, question_id)，覆盖写入
- 接口：PUT /spas/errorTag 保存；题目明细接口带回 errorCode / errorLabel
- 权限：与学生分析相同 spas:analysis:student
- 脚本：sql/spas_error_tag.sql（含字典）

## 9. 验收步骤

1. 同班两名同名学生：不填学号的行失败；填对学号的行成功，且不因姓名不同而拒收。
2. 下载模板可见学号、姓名及预填学生。
3. 某科最近校次 40、总分校次 10 时，学生分析该科显示落后 30。
4. 最近 3 场总分校次 20→30→45，规则 `RANK_DROP`、`>`、`10`、场次 3，执行后产生预警。
5. 最近一场数学校次比总分落后 25，规则 `SUBJECT_IMBALANCE`、`>`、`20` 触发，说明中含科目。
6. 有题未绑知识点时，发布和导入成绩均失败，已绑定且权重和为 1 的试卷可以通过。

7. 教师在题目明细中可为得分偏低题保存错因（审题/计算/概念/未做），刷新后仍可见。
