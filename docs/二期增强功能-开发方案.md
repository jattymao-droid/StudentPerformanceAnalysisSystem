# 学生学情分析系统 · 二期增强功能开发方案

> 基于现有 **RuoYi-Vue 3.9.2 + PostgreSQL + ruoyi-spas** 继续演进  
> 文档版本：v1.0 · 日期：2026-09-16  
> 前置文档：`docs/学生学情分析系统-开发方案.md`（一期闭环已落地）  
> 目标：在「采集 → 标注 → 导入 → 分析 → 预警 → 一生一册」之上，补齐 **干预闭环、报告导出、数据质量、维度增强**，让分析结果「准、细、可行动」。

## 2. 功能包详细设计

### F1 · 干预闭环（预警/薄弱 → 辅导 → 复测对比）【P0】

#### 2.1.1 业务故事

1. 教师在 **预警记录 / 学生薄弱表 / 班级排名** 点击「发起干预」  
2. 系统预填：学生、学科、薄弱知识点列表、触发来源（预警 ID 或知识点 ID）、建议目标（如加权得分率提升至 ≥60%）  
3. 教师补充辅导内容、下次复测建议试卷/日期，保存为干预任务  
4. 辅导过程继续写入 `spas_coach_log`，并关联 `intervene_id`  
5. 新成绩导入并重算后，系统自动计算 **复测对比**：  
   - 辅导前快照（任务创建时锁定的 `weighted_rate`）  
   - 辅导后当前快照  
   - 增益 Δ、是否达标、建议关闭或继续跟进  
6. 一生一册展示「干预时间线」：任务 → 辅导记录 → 效果结论

#### 2.1.2 数据模型

**新建表 `spas_intervene_task`**

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| intervene_id | bigserial PK | |
| student_id | bigint NOT NULL | |
| subject_id | bigint | |
| source_type | char(1) | 1=预警 2=薄弱点 3=手工 |
| source_id | bigint | warning_id 或 knowledge_id |
| knowledge_ids | varchar(500) | 逗号分隔，或改关联表 |
| title | varchar(128) | |
| target_rate | numeric(10,6) | 目标加权得分率 |
| baseline_rate | numeric(10,6) | 创建时综合/知识点基线 |
| baseline_json | text | 各知识点基线明细 JSON |
| status | char(1) | 0进行中 1已达标 2已关闭 3逾期 |
| owner_by | varchar(64) | 责任教师 |
| due_date | date | 计划复测日 |
| close_time | timestamp | |
| effect_rate | numeric(10,6) | 关闭时实测率 |
| effect_delta | numeric(10,6) | effect - baseline |
| effect_passed | char(1) | 0/1 |
| create_by / create_time / update_* / remark | | 沿用惯例 |

**扩展 `spas_coach_log`**

| 字段 | 说明 |
| :--- | :--- |
| intervene_id | 可空；关联干预任务 |
| knowledge_id | 可空；单次辅导聚焦知识点 |

**可选关联表 `spas_intervene_knowledge`**（知识点较多时优于逗号字段）

| intervene_id | knowledge_id | baseline_rate | current_rate（冗余可算） |

#### 2.1.3 接口设计

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/spas/intervene/list` | 分页列表（班级/学生/状态） |
| GET | `/spas/intervene/{id}` | 详情 + 知识点基线 + 辅导记录 |
| POST | `/spas/intervene` | 新建（可从预警带 `warningId`） |
| PUT | `/spas/intervene` | 更新计划/状态 |
| POST | `/spas/intervene/{id}/evaluate` | 手动触发效果评估（重算后） |
| POST | `/spas/intervene/from-warning/{warningId}` | 快捷创建 |
| GET | `/spas/intervene/student/{studentId}/timeline` | 一生一册时间线 |

**效果评估算法（`evaluate`）**

```
for each knowledge in task:
  current = spas_student_knowledge_stat.weighted_rate
  delta = current - baseline
task.effect_rate = attempt-weighted mean(current)
task.effect_delta = effect_rate - baseline_rate
task.effect_passed = effect_rate >= target_rate ? '1' : '0'
if passed -> 建议 status=1；教师确认后关闭
```

触发时机：

- 成绩导入 `recalculateByPaper` 成功后，异步/同步扫描该试卷学生的进行中任务并 `evaluate`  
- 班级「按新算法重算」后同样触发  
- 教师手动「评估效果」

#### 2.1.4 前端页面

| 页面 | 要点 |
| :--- | :--- |
| `views/spas/intervene/index.vue` | 任务列表、筛选、状态标签、达标着色 |
| 预警 `record.vue` | 操作列增加「发起干预」 |
| 学生分析薄弱表 | 「发起干预」预填知识点 |
| 一生一册 | 「干预时间线」卡片：基线 → 辅导 → Δ |
| 学生端 mine | 只读展示进行中任务与教师反馈 |

#### 2.1.5 验收标准

- [ ] 从预警一键创建任务，基线率与创建时刻快照一致  
- [ ] 导入新成绩并重算后，任务页可见 Δ 与是否达标  
- [ ] 一生一册时间线顺序正确  
- [ ] 校级领导不可新建/改状态（`assertCanWrite`）  
- [ ] 学生不可查看他人干预任务

### F2 · 学情报告导出【P0】

#### 2.2.1 业务故事

教师/班主任选择学生或班级 + 学科，点击「导出报告」，下载 PDF：含摘要 headline、KPI、薄弱清单、（可选）雷达/趋势图、干预建议摘要。

#### 2.2.2 技术方案

| 方案 | 说明 | 建议 |
| :--- | :--- | :--- |
| A. 后端模板引擎出 PDF | OpenPDF / Flying Saucer + HTML 模板 | **推荐**：权限与数据一致、可审计 |
| B. 前端 html2canvas + jsPDF | 实现快，排版弱、大数据卡顿 | 仅作原型 |
| C. Excel 明细 | 复用 `ExcelUtil` | 作为 PDF 补充，「导出明细」 |

本期采用 **A + C**：PDF 主报告 + Excel 明细可选。

#### 2.2.3 报告内容结构

**学生报告**

1. 封面：学校/班级/学号姓名/学科/生成时间  
2. 综合摘要（复用 `studentSummary.headline`）  
3. KPI：综合得分率、班均、与班差、严重/薄弱/关注数、置信度  
4. 薄弱知识点表（得分率、班均、Δ、练习次数、等级）  
5. 近 N 场趋势表（可选附图：服务端用 ECharts 导出图片成本高，一期可用表格）  
6. 进行中干预与最近辅导摘要  
7. 页脚：算法说明一句话（加权公式简述）

**班级报告**

1. 班级摘要 headline  
2. KPI + 薄弱学生名单（排名弱→强 Top20）  
3. 薄弱知识点 Top  
4. （可选）质量告警摘要条数  

#### 2.2.4 接口

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/spas/report/student/{studentId}` | `?subjectId=&format=pdf\|xlsx` |
| GET | `/spas/report/class/{deptId}` | `?subjectId=&format=pdf\|xlsx` |
| GET | `/spas/report/preview/student/{id}` | 返回 JSON 供前端预览（可选） |

权限：`spas:report:export`；路径级仍走 `checkStudentAccess` / `checkDeptAccess`。

#### 2.2.5 前端

- 学生分析 / 班级分析 / 一生一册 工具栏：「导出报告」  
- 导出中 loading；失败提示权限或无数据  

#### 2.2.6 验收标准

- [ ] 教师仅能导出权限范围内学生/班级  
- [ ] PDF 可打开，中文不乱码（字体嵌入或服务器中文字体配置）  
- [ ] 无成绩学生导出给出明确提示而非空文件  
- [ ] 导出操作记操作日志 `@Log`

### F3 · 数据质量看板【P1】

#### 2.3.1 目的

分析再准也怕「底数脏」。质量看板把影响精度的问题前置暴露。

#### 2.3.2 质量指标（首期）

| 编码 | 指标 | 计算要点 | 严重级别 |
| :--- | :--- | :--- | :--- |
| Q_BLANK_ZERO | 空分按 0 计入占比 | 近批导入中 score=0 且可判定为 blank 的比例（若未落标记，则用「整行有分但部分题为 0」启发式） | 提示 |
| Q_NO_KNOWLEDGE | 题目未绑定知识点 | `paper_question` 无 `question_knowledge` | 严重 |
| Q_WEIGHT_SUM | 权重和≠1 | 校验失败或历史脏数据 | 严重 |
| Q_LOW_ATTEMPT | 样本不足仍展示 | attempt_count &lt; min-attempts 的 stat 行占比 | 关注 |
| Q_MISSING_EXAM_DATE | 试卷无考试日期 | 影响近因加权与连续下滑 | 关注 |
| Q_PARTIAL_PAPER | 学生作答题数 &lt; 试卷题数 | 按 paper+student 统计 | 关注 |
| Q_ORPHAN_SCORE | 成绩指向已删/草稿异常卷 | 防护性检查 | 严重 |

> 说明：若需精确统计「blank-as-zero」，建议导入时在 `spas_score_detail` 增加 `score_source`（1手工 2导入 3空白置零），二期质量看板更准。

#### 2.3.3 数据与接口

可选：实时 SQL 聚合（首期）或日终写入 `spas_quality_snapshot`。

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/spas/quality/overview` | `?deptId=&subjectId=` 返回指标卡片 |
| GET | `/spas/quality/detail` | `?metric=Q_NO_KNOWLEDGE` 下钻列表 |

#### 2.3.4 前端

- `views/spas/quality/index.vue`：卡片 + 下钻表 + 跳转修复（试卷编辑/成绩页）  
- 首页 dashboard 增加「质量告警数」KPI（可选）  

#### 2.3.5 验收标准

- [ ] 故意去掉某题知识点后，看板出现 Q_NO_KNOWLEDGE 且可下钻到题号  
- [ ] 教师数据范围与 `@DataScope` / 教师多班一致  
- [ ] 不影响现有分析接口性能（质量查询可限 dept）

### F4 · 章节/单元维度学情【P2】

#### 2.4.1 说明

知识点树已有父子章节。现分析多落在叶子节点。增加「选中章节 = 汇总其下所有叶子 stat」。

#### 2.4.2 算法

```
chapter_rate(student, chapter) =
  attempt-weighted avg( weighted_rate of descendant leaf stats )
```

班级章节热力：学生 × 章节。

#### 2.4.3 接口增量

- `GET /spas/analysis/student/{id}/chapter-radar?subjectId=`  
- `GET /spas/analysis/class/{deptId}/chapter-overview?subjectId=`  

前端：知识点分析页允许选中非叶子节点并展示汇总（现禁用章节可选改为「汇总模式」）。

### F5 · 时间窗筛选【P2】

#### 2.5.1 说明

在全历史 + 近因衰减之外，提供显式窗口：`all` / `last30d` / `last90d` / `semester`（学期起止可配置）。

实现路径二选一：

| 路径 | 说明 |
| :--- | :--- |
| A. 查询期过滤 | 分析 SQL 增加 `exam_date >= ?`，**不改快照**（快照仍全量）；窗口指标即时聚合 |
| B. 窗口快照 | 另存 `spas_student_knowledge_stat_window` | 更重，不建议首期 |

**推荐 A**：学生趋势/雷达在窗口模式下走即时聚合接口；默认模式仍读快照（快）。

配置：`spas.analysis.default-window=all`。

#### 2.6.1 说明

## 4. 与现有算法的关系（必须遵守）

1. **不改变**一期公式默认语义：  
   `sample_w = knowledge_weight × difficulty_w × recency_decay`  
2. 干预基线必须在任务创建时 **冻结**，避免事后重算改写历史对比  
3. 报告中的「综合得分率 / 班均」必须与分析页 **同一口径**（练习次数加权）  
4. 质量看板只告警，不自动改成绩（改数需人工确认）  
5. 所有新写接口走 `SpasAccessService` + 校级只读拦截

## 8. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| PDF 中文乱码 | 打包开源中文字体；CI 校验字体文件存在 |
| 干预评估拖慢导入 | `auto-evaluate` 可配置；大班改异步（`@Async` + 进度） |
| 基线被全量重算污染 | 基线写入任务表，评估只读任务基线 |
| 质量 SQL 慢 | 限 dept + 索引（paper_id, student_id, knowledge_id） |
| 报告含敏感信息 | 权限校验 + 操作日志；学生端禁止班级报告 |
