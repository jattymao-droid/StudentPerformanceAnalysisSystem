# 知脉 · 组长检查 + 教师抽检 · 监管改进方案

> 文档编码：UTF-8  
> 版本：v1.3 · 日期：2026-10-04  
> 依托：`docs/spas-group-daily-practice-desktop.md`（分组、打卡、一体机、积分、S1～S5）  
> 定位：将主路径从「组员自报完成」改为「组长按标准检查、教师按风险抽检」  
> 原则：检查在座位（线下翻本抽问），一体机只结账；确认不隔夜、抽检打检查质量、激励不奖完成率

---

## 0. 为什么要改

现行一体机打卡降低了登记成本，监管仍主要盯 **「声称练过」**：

| 现状 | 问题 |
| :--- | :--- |
| 组员自填完成态 | 书名/页码/题号可空填；无抽查则空打卡成本极低 |
| 组长代提 + 次日确认 | 排队场景下代提必然出现；隔夜点确认几乎等于合谋 |
| 积分奖首条打卡、勾薄弱 +5、班内榜 | 行为被推向「可刷的提交」，如实报困难反而吃亏 |
| 教师看板三列（未交 / 有困难 / 代提过多） | 最容易做的是复制未交名单；最难做的抽检被放在旁路 Tab |

**结论：** 练习发生在座位上，一体机只是结账点。完成态应由 **看见书本的人** 给出，并由 **教师抽检** 校准「检查是否偏松」。

本方案 **有助于提高完成记录的可信度**，仍不替代对错批改与掌握度计算。组长默认只判断「做没做、写没写、能不能开口说思路」，会不会最终仍靠抽问与成绩。

## 1. 产品一句话

**教师布置同一小任务 → 轮值检查员在座位按脚本翻书抽问 → 组长到一体机一次登记全组结果 → 组员当日 PIN 确认或异议 → 教师按风险抽检 → 偏松则作废记录并取消当周组达标。**

有效监管公式（修订）：**系统筛组，组长查本，教师只处理抽检队列与困难摘要。**

## 2. 角色与负荷

| 角色 | 职责 | 明确不做 | 负荷上限 |
| :--- | :--- | :--- | :--- |
| 组员 | 按布置做题；向检查员出示练习本；当日 PIN 确认或异议 | 给自己判定「已完成」 | 确认 ≤10 秒 |
| 检查员（建议周轮换） | 按脚本翻指定页、抽问 1 题、给出状态 | 精批对错、代写作业 | 本组 5～8 分钟 |
| 组长 | 组织座位上的检查窗口；事后上机登记本组结果；把困难汇总成短摘要 | 在机器前做检查；自检自评；为冲达标全员勾完成 | 交单一屏完成 |
| 任课教师 | 布置任务；执行抽检；跟进困难/偏松 | 每天翻全班明细 | 每班每周抽检 1 轮，每组 ≥1 人 |
| 班主任 | 催「组检查单未交」 | 代替任课老师判会不会 | 看未结账组名单即可 |

规则：

- 一组 **4～6 人**，超过则拆组。
- 检查员可与组长为同一人；**组长本人由邻组检查员或教师抽检，禁止自检自评。**
- 轮换周期建议 **1 周**，避免催交权与检查权长期集中。

## 3. 主流程

### 3.1 教师：布置（检查的标准从这里来）

没有统一任务，组长只能看「有没有字」，组间不可比，教师也无法抽检。

每次布置（按班级 + 学科，可一周复用 3 次）必须包含：

| 字段 | 说明 |
| :--- | :--- |
| 应练日期或星期规则 | 如本周一二四；默认周达标次数而非强制天天一条 |
| 知识主题 | 1 个主主题（可多选辅主题）；尽量来自知识点树 |
| 书名 | 本班统一，禁止各组自拟 |
| 页码起止 | 如 32–35 |
| 题号范围 | 如 1,2,5 / 练习 B 第 4～7 题 |
| 「已完成」操作定义 | 见 §4，随任务展示给组长 |

一期允许教师从模板复制上周任务。组员 **不再自由找题作为默认义务**；自由加练可另开「加练」且不计入组达标。

### 3.2 座位上：练习

学生按布置做题。一体机 **不是练习场**，不在机前做题。

### 3.3 检查窗口：脚本（印成组内一张卡）

每人约 30～60 秒：

1. 打开指定书、指定页，看是否有书写痕迹。  
2. 在布置题号中抽 **1 题**，问：「这题你怎么下手？」能开口说步骤即可，不要求当场判满分。  
3. 给出唯一状态（见 §4）。  
4. 「有困难」必须带 **一句卡点**（题号或一句话）。  
5. 人未到、没带本、请假：用对应状态，**禁止记已完成**。

超时聊天即失败；没有脚本，8 分钟窗口会被吃掉。

### 3.4 一体机：本组一次结账

**检查不在线上做。** 翻本、抽问、给状态发生在座位；一体机不是检查场，只把已经看过的结果登进去。

组长登录 → 「登记检查结果」→ 当天任务只读带出（对照刚才查过的书页）→ 按线下结论给每个组员点状态 → **全员都有状态才能提交**（请假算有状态）。

不要让组长为每个组员填写完整打卡表（书名/页码/题号）。那些字段来自布置，检查单只记录 **人 × 状态 × 卡点**。不要对着屏幕重新翻一遍组员的电子记录来代替看本子。

### 3.5 组员：当日确认

提交后进入「待确认」：

- **属实**：本人 PIN 当日确认。  
- **异议**：一键异议，该生该次 **在教师处理前不算完成、也不计入组长达标分**，并进入 **抽检必抽**。

**取消隔夜确认。** 次日确认成本过低，会把代填合法化。

未在当日窗口确认的，记「未确认」：不奖分；教师看板可见；不自动当成已完成。

### 3.6 教师：按风险抽检

系统生成队列（算法见 §6），教师对书问布置中的 1 题，录入三档结果（§6.2）。偏松自动作废该次学生记录、记检查不准、取消当周组达标。

### 3.7 困难：当天被接住

「有困难」不是失败态：

- 一体机给组员一句下一步（找老师 / 看该主题 / 明日办公室）。  
- 教师看板按 **知识点合并** 困难摘要，而不是 N 条流水。  
- 连续有困难却从未抽检、从未点「已知晓/转干预」的，预警级别 **高于普通未交**。

## 4. 完成态字典

| 状态 | 代码建议 | 何时使用 | 可否点「已完成」替代 |
| :--- | :--- | :--- | :--- |
| 已完成 | `1` | 指定页有书写 **且** 抽问能开口说思路 | — |
| 部分完成 | `2` | 有书写但明显未做完，或抽问说不出 | 否 |
| 未做 | `0` | 看到书但指定范围空白 | 否 |
| 有困难 | `3` | 做了但卡死；必须填卡点 | 否（有字且卡死用本态，不用已完成） |
| 请假 | `L` | 事假病假等，组长可见即可 | 否 |
| 人未到/没带本 | `A` | 检查窗口见不到本 | 否 |
| 异议 | `D` | 组员否认检查结果 | 系统写入，组长不可选 |

只翻到有字、未抽问，**最高记部分完成**。

如实报未做 / 有困难，**不得重于** 未做却报已完成。抽检发现后者：该次作废 + 检查不准。

## 5. 数据与接口（相对现行模型的增量）

现行 `spas_practice_log` 仍可作「人 × 日 × 学科」行；完成依据改为检查单，而不是组员自提。

### 5.1 建议新表

```sql
-- 教师布置（班 + 学科 + 应练日）
create table spas_practice_assignment (
  assignment_id bigserial primary key,
  dept_id       int8 not null,
  subject_id    int8 not null,
  assign_date   date not null,
  knowledge_id  int8,                 -- 主主题，可另表多选
  book_name     varchar(200) not null,
  page_from     int4,
  page_to       int4,
  question_text varchar(500) not null,
  due_count_week int2 default 3,      -- 本周应查次数（周达标）
  status        char(1) default '0',
  create_by     varchar(64),
  create_time   timestamp,
  unique (dept_id, subject_id, assign_date)
);

-- 本组一次结账
create table spas_practice_checkout (
  checkout_id   bigserial primary key,
  assignment_id int8 not null,
  group_id      int8 not null,
  practice_date date not null,
  leader_student_id int8 not null,
  checker_student_id int8 not null,   -- 轮值检查员
  submit_time   timestamp,
  device_code   varchar(64),
  status        char(1) default '0',  -- 0有效 1作废（整单偏松可作废）
  unique (group_id, practice_date, assignment_id)
);

-- 检查单明细（一人一行）
create table spas_practice_checkout_item (
  item_id       bigserial primary key,
  checkout_id   int8 not null,
  student_id    int8 not null,
  finish_status varchar(2) not null,  -- 见 §4
  difficulty_note varchar(500),
  member_ack    char(1) default '0',  -- 0待确认 1属实 2异议 3超时
  ack_time      timestamp,
  unique (checkout_id, student_id)
);

-- 抽检（打在 item 上，可冗余 checkout）
-- 可扩现行 spas_practice_log.spot_*，或独立表便于记「偏松」
create table spas_practice_spot (
  spot_id       bigserial primary key,
  item_id       int8 not null,
  student_id    int8 not null,
  group_id      int8 not null,
  checker_student_id int8,
  spot_result   char(1) not null,     -- 1一致 2偏松 3偏严
  spot_by       varchar(64),
  spot_time     timestamp,
  spot_remark   varchar(500)
);
```

与掌握度关系 **不变**：检查单 **不写入** `KnowledgeStatCalculator` / `avg_rate`。抽检通过也不自动当考试分。

### 5.2 API 草案

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| POST/GET | `/spas/practice/assignment` | 教师布置 / 查询当日任务 |
| GET | `/spas/practice/checkout/today` | 组长：任务只读 + 组员名单 + 已填状态 |
| POST | `/spas/practice/checkout` | 组长提交全组检查单（全员有状态） |
| PUT | `/spas/practice/checkout/item/{id}/ack` | 组员属实/异议（须本人，当日） |
| GET | `/spas/practice/stat/spot-queue` | 教师：风险抽检队列 |
| PUT | `/spas/practice/spot/{itemId}` | 录入一致/偏松/偏严；触发作废与组达标重算 |
| GET | `/spas/practice/stat/alerts` | 修订：组未结账 / 抽检偏松 / 困难摘要 / 未确认 |

组员 `POST /spas/practice` 降为 **加练或无组补登**，不再作为默认完成依据。  
`POST /spas/practice/proxy` **停用或仅管理员补录**，由 checkout 取代。

## 6. 抽检规则

### 6.1 抽样权重（概念）

每周每组至少 1 人。在此基础上提高下列对象的权重：

1. 本组该次 **全员已完成**  
2. 本学期 **从未抽到** 的学生  
3. 任职检查员期间 **偏松次数 > 0** 的检查员及其组  
4. 连续多日 **有困难** 却从未被问过的学生  
5. 存在 **异议** 的 item（必抽，权重最高）

试点前 **两周** 每组 2 人，用于给「已完成」定标；之后降到每组 1 人。

### 6.2 抽检结果

| 结果 | 含义 | 系统动作 |
| :--- | :--- | :--- |
| 一致 | 与检查单相符 | 该条视为核实；可发核实积分 |
| 偏松 | 组长/检查员写已完成（或等价），现场对不上 | 该生该次作废；组记 1 次检查不准；**当周组达标取消**；该检查员下周必抽 |
| 偏严 | 现场好于记录（少见） | 仅校正，不惩罚组员；可提示检查员标准过严 |

连续 **2 周** 出现偏松：暂停该检查员资格一周，由教师或邻组接管。

### 6.3 队列交互

教师监管页 **默认 Tab = 抽检队列**（带书名、页码、题号、组长填写状态）。  
现场只点三档 + 可选一句话。不要先点「生成本周随机名单」再去明细里找人。

## 7. 周达标与积分

### 7.1 组周达标（同时满足）

1. 本周应查次数内，检查单 **按时交齐**（含请假状态）。  
2. 抽检 **无偏松**（或一致率 ≥ 学校配置，默认「无偏松」更简单）。  
3. 「有困难」人次均有教师 **已知晓或已转干预**。

**不用**「全员已完成」作为达标条件。

### 7.2 积分（修订现行 8B）

| 事件 | 建议 | 说明 |
| :--- | :--- | :--- |
| 组员检查记录 | 仅核实后发分 | 抽检一致；或当周本组无偏松且本人无异议 |
| 命中薄弱 +5 | **取消或大幅降低** | 避免只勾主题 |
| 组长/检查员 | 奖按时交单 + 低偏松 | **不奖** 高完成率 |
| 代提 50% | **删除** | 已无代提主路径 |
| 班内个人周/总榜 | 学生首页 **隐藏或改为组达标灯** | 避免公开羞辱与卷榜 |
| 如实报困难 | 不扣分；抽检确认不会则 **不扣组达标** | 保护诚实 |

日封顶、`biz_key` 幂等、掌握进步发分可保留；进步发分仍要求「近期确有核实练习」。

## 8. 教师与一体机界面

### 8.1 教师 Web（监管页改默认）

进入即三块，不要默认全班明细：

1. **组未结账**（催组长）  
2. **抽检队列**（一致 / 偏松 / 偏严）  
3. **困难摘要**（按知识点合并人数 + 转干预）

辅栏：未确认、异议、检查不准次数、组达标灯。  
提交率、个人积分榜降为次要 Tab。

班主任与任课可分权：班主任只看未结账；任课看抽检与困难。

### 8.2 一体机

| 页面 | 内容 |
| :--- | :--- |
| 组长首页 | 今日任务摘要；主按钮「登记检查结果」（强调先线下后上机） |
| 登记页 | 组员大按钮状态机；有困难展开必填；全员就绪才可提交；文案写明「检查已在座位完成」 |
| 组员首页 | 今日是否已检查、待确认/已确认、困难下一步；无「自己登记完成」主按钮 |
| 确认页 | 展示组长给的状态与卡点；属实 / 异议 |
| 教师不在一体机抽检 | 抽检走 Web，避免教室机器被老师占满 |

组员自提入口降到「加练（不计入达标）」或设置页，避免两套官方完成并存。

## 9. 与现行方案对照

| 项目 | `spas-group-daily-practice-desktop.md` | 本改进 |
| :--- | :--- | :--- |
| 完成依据 | 组员自提 / 代提 | 组长检查单 + 当日确认 |
| 书名页码题号 | 每次手填 | 来自教师布置，检查单只读带出 |
| 代提 | 主路径之一，次日确认 50% 积分 | 停用；结账取代 |
| 抽查 | S5 独立 Tab，随机名单 | 主流程；风险加权；偏松打组达标 |
| 异常三列 | 未交 / 有困难 / 代提过多 | 组未结账 / 偏松 / 困难摘要 |
| 积分 | 打卡、勾薄弱、班榜 | 核实与低偏松；组达标灯 |
| 节奏 | 易滑向每日一条 | 周应查次数（默认 3） |
| 最小监管包 | S1～S5 仍有效，但 S1 代提列改为检查不准 | S5 升级为抽检闭环 |

现行表字段（`proxy_flag`、`spot_status`、积分流水）可迁移：  
`spot_status` 扩展偏松；checkout 落地前可用「组长代提 + 当日确认 + 禁止组员自提」做 **过渡期**，但验收仍以检查单为准。

## 10. 明确不建议

- 组长为冲提交率或积分给全员勾已完成  
- 组员隔夜确认、或确认与检查脱节  
- 个人公开倒排、把完成率当班主任考核唯一指标  
- 检查单自动写入掌握度  
- 每天全员拍照（仅偏松/异议补一张指定页）  
- 一组超过 6 人还不拆组  
- 未经校方确认的家长端实时催作业  
- 让组长负责讲题对错（加重负担并刺激造假）

## 11. 分期落地

| 阶段 | 内容 | 说明 |
| :--- | :--- | :--- |
| **M0 规则试点** | 不改库：教师纸质布置；组长用现有代提按状态交；老师用现有抽查点偏松；班内关掉个人榜展示 | 1 个班 2 周，验证 8 分钟窗口与轮换 |
| **M1 布置 + 检查单** | assignment + checkout API；桌面端组长结账；组员当日 PIN 确认/异议；禁用日常代提 | 替换主路径 |
| **M2 风险抽检闭环** | spot-queue；偏松作废；组达标；困难按主题合并 | 教师 30 秒能开始抽 |
| **M3 积分与看板对齐** | 核实才发分；组达标灯；监管默认三块 | 避免与旧 8B 两套激励 |

试点复盘指标（两周）：

- 空打卡代理指标：抽检偏松率（目标下降）  
- 组长负荷：检查窗口是否经常超过 8 分钟  
- 诚实度：有困难上报率是否因「不扣达标」而上升  
- 教师时长：每日是否只处理队列而非翻明细  
- 异议率：过高说明检查不公，过低结合偏松看是否不敢提异议

## 12. 验收标准

- [ ] 当日有布置时，组长检查单自动带出书名/页码/题号，组长不可改布置内容  
- [ ] 未全员给出状态无法提交检查单

## 13. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 小组合谋全员已完成 | 全员完成组提高抽检权重；偏松取消组达标并暂停检查员 |
| 组长负担过重 | 4～6 人、5～8 分钟脚本、周轮换、不判对错 |

## 14. 给师生的短文案（可贴教室）

**给组员：** 按黑板上的书和题做。组长来检查时请拿出本子。机器上只确认「检查属实」或「有异议」。不会因为说「这题不会」扣小组分。

**给检查员：** 在座位翻到指定页 → 抽一题问怎么下手 → 记下状态。没看见本子不能记已完成。上机只是把刚才的结论点进去。我们抽查的是你查得准不准，不是你们组交得多不多。

**给老师：** 每周打开抽检队列，按名单问一题。点「偏松」即可，系统会作废该次并取消该组当周达标。困难看合并摘要，需要的再转辅导。
